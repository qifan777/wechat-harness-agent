# Proposal

## Why

现有的“个人资料助理”仅支持在终端通过 `npm run ask` 进行单次命令行问答，无法在手机端随时随地发起对话。将该助理接入微信个人号（ClawBot），可以让用户在微信中直接发送文字、语音、图片或文件等消息并获得助理回复，同时为后续章节的会话记忆、资料读写与定时通知提供移动端交互通道。

## What Changes

- 新增命令行入口 `npm run wechat`，启动微信消息监听常驻进程；原有的 `npm run ask -- "问题"` 单次问答入口保持可用且行为不变。
- 引入并锁定 `@wechatbot/wechatbot`（精确版本 `2.2.0`，不使用 `latest`、`^` 或 `~`）接入微信：首次启动通过 `bot.login({ callbacks })` 在终端输出扫码登录引导链接，登录成功后将微信凭证与 `context_token` 保存在项目本地专属目录并加入 `.gitignore`，后续启动自动复用已有凭证。
- 支持所有类型的微信私聊消息：收到文字、语音（直接使用微信服务端自带 ASR 转写后的 `msg.text`）、图片、文件、视频以及引用回复（`msg.quotedMessage`）时，先通过 `bot.sendTyping(msg.userId)` 向微信发送“正在输入”状态提示（并在生成与发送期间每 4 秒续期一次，全部发完后调用 `bot.stopTyping`），再将消息文本、引用上下文或媒体链接/本地路径一并交给现有的“个人资料助理” Mastra Agent，由 Agent 根据自身能力尝试处理并生成中文回复。仅当消息既无有效文本又无任何媒体内容时忽略或返回简短中文提示。
- 增加长回复切分、发送限速与频控退避机制：当回复长度超过单条阈值（1500 字符，处于微信单条上限及 2000 字符安全线以内）时，优先按段落（换行）或句子边界切分为多条消息依次发送，相邻两条消息之间间隔不少于 1.5 秒（1500ms）；若遇到微信服务端频控 `prepare failed` 错误，等待 5 秒后重试一次。
- 增强常驻进程容错与安全边界：单次模型调用或微信消息发送失败时，向用户回复简短中文错误提示，进程保持运行并继续监听后续消息；API Key 与微信登录凭证不得出现在代码、日志、终端输出和发给用户的消息中。
- 本变更不包含：多轮会话记忆、偏好记忆、定时任务、群聊支持。

## Capabilities

### New Capabilities
- `wechat-agent`: 微信常驻监听入口、扫码登录与本地凭证复用、全类型私聊消息（文字、语音转写、媒体链接/路径、引用消息）接入、“正在输入”状态触发与续期、长回复分段与限速退避发送、单次异常容错及凭证/密钥脱敏保护。

### Modified Capabilities
无。直接复用第 1 章已归档的 `minimal-agent` 规格中的模型配置、Mastra Agent 与内置 `Workspace` 工具。

## Impact

- **前置状态与依赖关系**：当前仓库中 `openspec/changes/minimal-agent/` 尚未实施与归档（`src/` 下仅有 `.gitkeep`）。实施本变更时需要复用 `minimal-agent` 定义的配置加载、密钥脱敏与 Mastra Agent 工厂模块（若尚未实施 `minimal-agent`，需先完成其基础模块或一并落地），同时保持 `npm run ask` 独立可用。
- **代码与配置**：预计新增微信通道入口与消息处理模块（如 `src/wechat.ts` 及消息格式化、分段/限速辅助函数），更新 `package.json`（新增 `wechat` 脚本与锁定版本的 `@wechatbot/wechatbot` 依赖）、`package-lock.json`、`.gitignore`（忽略本地微信登录凭证及下载缓存目录/文件）以及 `README.md`。
- **测试与验收**：新增针对全类型消息（文字、语音转写、媒体路径、引用消息）格式化、长文本按段落/句子切分、发送间隔限速与 `prepare failed` 退避重试、单次调用异常不退出及敏感信息遮蔽的自动化单元测试/模拟测试；真实微信扫码登录与收发消息由用户在本地终端与手机微信中人工验收。
