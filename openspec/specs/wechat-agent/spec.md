# wechat-agent Specification

## Purpose

为“个人资料助理”提供基于微信个人号（ClawBot）的常驻消息监听与交互通道，支持终端引导扫码登录与本地凭证自动复用、全类型私聊消息（文字、语音自动转写、图片/文件/视频媒体链接或路径、引用消息）响应、“正在输入”状态提示、长回复分段与发送限速退避、常驻进程容错以及凭证与密钥脱敏保护，同时保持原有 `npm run ask` 单次命令行问答入口独立可用。

## Requirements

### Requirement: 微信常驻监听入口与原有命令行共存
系统 SHALL 提供 `npm run wechat` 命令以启动微信消息监听常驻进程；启动前 SHALL 校验模型环境变量配置，缺失配置时输出简短中文错误并以非零状态码退出。原有的 `npm run ask -- "问题"` 单次问答入口 SHALL 保持可用且行为不变。

#### Scenario: 启动微信常驻监听进程
- **GIVEN** 模型环境变量配置完整有效
- **WHEN** 用户在终端运行 `npm run wechat`
- **THEN** 进程启动微信客户端连接并在连接成功后保持常驻监听状态，不自动退出

#### Scenario: 缺少模型配置时拒绝启动微信监听
- **GIVEN** `MODEL_BASE_URL`、`MODEL_API_KEY` 或 `MODEL_NAME` 中任一配置缺失或为空白
- **WHEN** 用户运行 `npm run wechat`
- **THEN** 终端输出简短中文缺失环境变量提示并以退出码 1 结束，不发起微信连接或模型调用

#### Scenario: 原有命令行问答保持可用
- **GIVEN** 微信通道代码已合入项目且模型配置有效
- **WHEN** 用户运行 `npm run ask -- "用一句话介绍你自己"`
- **THEN** 系统按单次问答模式打印中文回答并以退出码 0 结束，不启动微信监听进程

### Requirement: 扫码登录引导与本地凭证持久化复用
系统 SHALL 在首次启动（本地无有效微信登录凭证）时通过 `bot.login({ callbacks })` 截获登录二维码链接并在终端输出中文引导提示与扫码登录信息，登录成功后将凭证与会话上下文（含 `context_token`）持久化保存在项目本地专属目录中。后续启动时系统 SHALL 自动复用本地已保存的凭证直接建立连接。本地微信登录凭证目录或文件 MUST 被 `.gitignore` 忽略。

#### Scenario: 首次启动终端引导扫码登录
- **GIVEN** 本地不存在已保存的微信登录凭证
- **WHEN** 用户运行 `npm run wechat`
- **THEN** 终端显示等待微信扫码登录的中文引导及扫码链接，用户扫码确认后将凭证写入本地忽略目录并进入消息监听状态

#### Scenario: 重启后自动复用本地登录凭证
- **GIVEN** 本地已存在有效的微信登录凭证文件
- **WHEN** 用户停止进程后再次运行 `npm run wechat`
- **THEN** 系统直接加载本地凭证建立连接并进入消息监听状态，无需重新扫码

#### Scenario: 登录凭证被 Git 忽略
- **GIVEN** 本地已生成微信登录凭证目录或文件
- **WHEN** 执行 `git status` 或 `git check-ignore` 检查凭证路径
- **THEN** 微信登录凭证目录及文件处于被 Git 忽略状态，不会出现在未跟踪或待提交列表中

### Requirement: 全类型私聊消息接入与“正在输入”状态提示
系统 SHALL 支持所有类型的微信私聊有效消息（包括纯文字、微信原生及 Unicode 表情、语音消息、图片、文件、视频以及带引用内容 `quotedMessage` 的消息），并准确区分扫码主人（`creds.userId`）与机器人自身（`creds.accountId`）。收到私聊有效消息时，系统 SHALL 先通过 `bot.sendTyping(msg.userId)` 触发微信“正在输入”状态提示，并在模型生成及多段回复发送期间定时续期（默认每 4 秒一次），待全部回复分段发送完毕后再调用 `bot.stopTyping(msg.userId)` 结束状态；消息内容（语音直接使用微信服务端自带 ASR 转写后的 `msg.text`；图片、文件、视频等媒体提取其 URL 或本地路径及元信息；引用消息附带被引用内容）组装为输入文本交给现有的“个人资料助理” Agent，由 Agent 根据自身能力尝试处理并生成中文回复。每次问答独立，不附带多轮历史、偏好记忆、定时任务，也不响应群聊消息。

#### Scenario: 收到文字或语音消息先触发正在输入再回复
- **GIVEN** 微信常驻进程处于监听状态
- **WHEN** 用户在微信私聊中发送文字消息“用一句话介绍你自己”，或发送一段已被微信自动转写为 `msg.text` 的语音消息
- **THEN** 系统在调用模型前先触发该会话的“正在输入”状态，随后将文本交给“个人资料助理” Agent 并将生成的中文回答发送给用户

#### Scenario: 收到图片、文件或视频等媒体消息交给 Agent 处理
- **GIVEN** 微信常驻进程处于监听状态
- **WHEN** 用户在微信私聊中发送一张图片、一个文件或一段视频（或同时附带引用消息）
- **THEN** 系统不拦截该消息，先触发“正在输入”状态，再将媒体的 URL/本地路径、类型描述及附带文本或引用内容一并传给 Agent，并将 Agent 的中文回复发送给用户，进程保持正常运行

#### Scenario: 连续两条消息无多轮记忆且忽略群聊
- **GIVEN** 微信常驻进程处于监听状态
- **WHEN** 用户先后发送两条私聊消息，或群聊中产生消息
- **THEN** 第二次私聊模型请求不携带第一条消息的对话历史，群聊消息不触发模型调用或回复

### Requirement: 长回复分段切分、发送限速与频控退避
Given Agent 生成的回复超过单条消息长度上限（默认阈值为 1500 字符，且不超过 2000 字符）时，系统 SHALL 自动优先按段落（换行符）或句子边界（句号、问号、叹号等）切分为多条消息，按顺序依次发送；无自然边界的超长片段 SHALL 按阈值硬切分。相邻两条发送的消息之间 SHALL 留出不少于 1.5 秒（1500 毫秒）的间隔；当发送接口返回 `prepare failed` 频控错误时，系统 SHALL 等待不少于 5 秒（5000 毫秒）后进行退避重试。

#### Scenario: 超长回复按段落或句子切分并限速发送
- **GIVEN** Agent 生成了一段长度为 3200 字符、包含多个段落和句子的中文回复
- **WHEN** 系统向微信用户发送该回复
- **THEN** 回复被优先在段落或句子边界处切分为每条不超过 1500 字符的多条消息，按原文顺序依次发送，且相邻两条消息发送间隔不少于 1500 毫秒

#### Scenario: 遇到 prepare failed 时退避 5 秒重试
- **GIVEN** 系统正在向微信用户发送回复消息
- **WHEN** 某次发送触发微信服务端频控并抛出 `prepare failed` 错误
- **THEN** 系统等待至少 5000 毫秒后自动重试发送该分段，恢复正常送达且进程不退出

#### Scenario: 短回复单条直接发送
- **GIVEN** Agent 生成了一段长度不超过 1500 字符的中文回复
- **WHEN** 系统向微信用户发送该回复
- **THEN** 系统以单条消息完整发送，不进行多余切分或额外等待

### Requirement: 常驻进程异常容错
单次模型调用失败、返回空回答、“正在输入”状态触发失败或微信消息发送（含重试后）失败时，系统 SHALL 捕获异常并（在发送通道可用时）向用户回复简短中文错误提示，常驻监听进程 MUST 保持运行不退出，继续处理后续消息。

#### Scenario: 单次模型调用失败后进程继续可用
- **GIVEN** 微信常驻进程正在运行，某次收到用户消息后模型服务返回错误或超时
- **WHEN** 系统捕获到本次模型调用异常
- **THEN** 系统向该微信用户发送简短中文错误提示，进程不崩溃退出；当用户随后发送下一条消息时，系统仍能正常接收并处理

#### Scenario: 正在输入状态或消息发送异常不导致进程退出
- **GIVEN** 微信常驻进程正在运行
- **WHEN** 触发“正在输入”状态或发送回复消息时发生网络/接口异常
- **THEN** 异常被受控捕获并记录脱敏后的简短中文错误日志，常驻进程不抛出未捕获异常且不退出

### Requirement: 凭证与密钥脱敏及依赖版本锁定
系统 MUST 不在源代码、日志、终端输出或发送给微信用户的任何消息（包括正常回复与错误提示）中暴露 `MODEL_API_KEY` 或微信登录凭证内容。新增的 `@wechatbot/wechatbot` 及相关直接依赖 SHALL 使用精确版本号（无 `latest`、`^`、`~`）并锁定在 `package-lock.json` 中。

#### Scenario: 模型回复或错误中包含敏感信息时自动遮蔽
- **GIVEN** 模型返回文本或异常信息中意外包含当前配置的 `MODEL_API_KEY` 或本地微信凭证令牌字符串
- **WHEN** 系统准备向微信用户发送消息或向终端打印日志
- **THEN** 对应敏感字面值全部被遮蔽替换，终端输出与微信消息中均不出现原始密钥或凭证

#### Scenario: 依赖版本精确锁定检查
- **WHEN** 检查 `package.json` 中的依赖声明与 `package-lock.json`
- **THEN** `@wechatbot/wechatbot` 及全部直接依赖均为精确版本号，不包含 `latest`、`^` 或 `~`
